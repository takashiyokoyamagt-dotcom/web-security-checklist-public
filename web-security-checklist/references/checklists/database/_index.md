# データベースセキュリティ（言語非依存。索引）

Webアプリがデータベースを使う場合に確認する項目です。`principles.md` の「5. データベース」を詳細化したもので、ORM・ドライバ別のコード例は `references/lang/<言語名>.md` の「データベース」節にあります。

## 読み方

| ファイル | 内容 | 読む条件 |
| --- | --- | --- |
| `sqli.md` | SQL・NoSQLインジェクション、動的SQL、ストアド | DBを使う場合は常に（入力値検証のRedも読んでよい） |
| `access.md` | DBアカウントの権限、職務と知る必要による絞り込み | DBを使う場合は常に |
| `data-protection.md` | 接続情報、保存データの暗号化、シード・本番データ、ファイル権限 | DBを使う場合は常に |
| `network-tls.md` | DB接続のTLS、接続先の設定、DBサーバの配置・待受・分離 | DBを使う場合は常に |
| `logging.md` | DBエラーの扱い、監査ログ | DBを使う場合は常に |
| `ops-requests.md` | リポジトリでは確かめられない運用の確認依頼 | 監査の最後（報告書の確認依頼を作るとき） |

## 項目の形式

各ファイルの表は `ID | 証跡 | 重大度目安 | 確認内容 | 検出の手掛かり | 根拠` の6列です。

- **証跡**: SRC＝ソースコード、CFG＝設定・IaC・マイグレーション、OPS＝運用でしか確かめられない。`SRC+OPS` のように複数を書いた項目は、SRC・CFGで見える範囲だけを指摘にする。
- **OPSの扱い**: 稼働中の状態（実際の待受、適用済みのFWルール、ファイル権限、ログの集約）はリポジトリから証明できない。OPSだけの項目、または設定の記述が無いことだけを根拠にする項目は、指摘にせず `ops-requests.md` の確認依頼にする。
- **検出の手掛かり**: 設定や記述の「存在」を示すだけで、稼働状態の証明ではない。指摘の本文では「設定ファイルにこう書かれている」と事実の範囲で書く。
- **重大度目安**: 最終の重大度はCVSSで決める（`references/cvss/cvss.md`）。
- **根拠**: ISMはオーストラリア政府のInformation Security Manual（2026-09版、Guidelines for Database Systems。確認日: 2026-11-07）の管理策ID。CWEは具体的な番号だけを付ける。

## レビュー時の着眼点（Red Team視点の例）

- 「このクエリのこのパラメータに `' OR '1'='1` を入れたらどうなるか」「保存した値が別のクエリに連結されないか（二次SQLi）」
- 「このORMメソッドに配列やオブジェクト（`{"$ne": null}` 等）を渡すと、意図しない条件や更新対象にならないか」
- 「このIDを他ユーザーのIDに書き換えたら、そのレコードを取得・更新できないか」
- 「接続文字列やパスワードが `git log` や設定ファイル、CIの定義に残っていないか」
