# 運用の確認依頼（OPS）

リポジトリでは確かめられない事項を、指摘ではなく確認依頼として報告書に載せる。対象アプリがDBを使う場合だけ出し、件数は10件までにする（該当が多いときは重大度目安の高い順）。同じ内容の重複は1件にまとめる。指摘（5節）にした事項は、ここに重ねて載せない。

| ID | 確認依頼 | 確認の方法の例 | 根拠 |
| --- | --- | --- | --- |
| DB-OPS-01 | データベースの台帳（名前、所有者、置き場所、保存データの分類）があり、定期的に見直されているか | 台帳の文書と最終更新日 | ISM-1243 |
| DB-OPS-02 | 本番DBの接続ユーザーに実際に付いている権限が、職務と最小権限に合っているか | `\du`・`SHOW GRANTS` の結果と権限の設計書の照合 | ISM-1255、ISM-1268 |
| DB-OPS-03 | DBサーバの実際の待受アドレスと、適用済みのFW・セキュリティグループの規則が、設定ファイルどおりか | `ss -ltnp`、クラウドの規則の一覧 | ISM-1271、ISM-1272 |
| DB-OPS-04 | DBサーバがWebサーバ・利用者の端末と別のホスト・ネットワークにあり、環境（本番・ステージング・開発）ごとに分離されているか | ネットワーク構成図、ホストの一覧 | ISM-1269、ISM-1270、ISM-1273 |
| DB-OPS-05 | DB接続のTLSの版と暗号スイートが、組織の暗号の基準に合っているか | `pg_stat_ssl`、`SHOW STATUS LIKE 'Ssl_cipher'` | ISM-1277 |
| DB-OPS-06 | データファイル・ダンプ・バックアップの実際のファイル権限と保管場所 | `ls -l` でのデータディレクトリの権限、バックアップの保管先 | ISM-1256 |
| DB-OPS-07 | 非本番環境に本番データが無いか。ある場合は本番同等に保護し、マスキングしているか | ステージングのデータの出所の記録 | ISM-1274 |
| DB-OPS-08 | DBの監査ログが実際に取得され、中央に集約され、保管期間が決まっているか | ログ基盤での直近のDBイベントの検索 | ISM-1537 |
| DB-OPS-09 | 保存データの分類（機微度）が決まっており、分類に応じた保護が適用されているか | データ分類の文書 | ISM-0393 |
| DB-OPS-10 | 稼働中のDBに既定・共有・未使用のアカウント（`postgres`・`root`・`sa`等）が残らず、既定のパスワードが変えてあるか | ユーザーの一覧と最終ログイン日時 | CWE-1392 |
| DB-OPS-11 | DBサーバ・DBソフトの版がサポート中で、セキュリティ修正が当たっているか | `SELECT version()`、パッチ適用の記録 | CWE-1395 |

書き方: 報告書の確認依頼の表に、IDと確認依頼、その依頼を出した理由（リポジトリで見えたこと。例「compose で 5432 を公開している」）を1行ずつ書く。理由が無い依頼（一般論だけの依頼）は出さない。ただしDB-OPS-01は理由が無くても出してよい。
