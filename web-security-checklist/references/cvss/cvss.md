## CVSSスコアの算定（モード2/3共通）

採用が決まった指摘（CONFIRMED/PLAUSIBLE）ごとに、CVSS（Common Vulnerability Scoring System）
v3.1・v4.0の両方でスコアを算定する（手順5f）。**重大度(Critical/High/Medium/Low)はCVSS v3.1の
定量的重大度区分を正とする**（Arbiterの主観ではなく、この客観的な基準に一本化する）。
CVSS v4.0のスコアも必ず併記するが、重大度の判定・指摘の並び順・サマリー表の集計はv3.1を基準にする
（v3.1とv4.0で重大度区分が食い違う場合もそのまま両方提示し、隠さない）。

### 環境メトリクスの確認

モード2手順2・モード3手順0で、修正案監査レビューの厳格度確認と同じAskUserQuestionに、以下の
設問も含める（特に指定がなければ既定の「反映しない」で進めてよい）:

- **反映しない（基本メトリクス(Base)のみ、既定）**: 対象システムの重要度に関する情報を使わない。
- **重要度が特に高い**: 対象システムが本番環境で、機密性・完全性・可用性のいずれも重視される
  （例: 個人情報・決済情報を扱う本番サービス）。CVSS環境メトリクスの機密性/完全性/可用性要求
  （CR/IR/AR）をいずれも`H`として扱う。
- **一般的な業務システム相当**: 特別な重要度の偏りがない一般的な業務システム。CR/IR/ARをいずれも
  `M`として扱う。
- **その他（自由記述）**: 上記に当てはまらない場合、ユーザーの自由記述（例:「可用性より機密性を
  重視」「社内限定ツールで可用性要求は低い」）から、Arbiterが機密性・完全性・可用性それぞれの
  要求度をH/M/Lで判定する。判定した理由を一言記録し、リスク分析章（`references/cvss/cvss-scoring.md`「リスク分析章への反映」節）にそのまま使う。

環境メトリクスを反映する場合、CR/IR/ARの値はCVSS v3.1・v4.0の両方のベクターに同じ値で追加する
（v3.1は`CR`/`IR`/`AR` + 必要なら`MAV`等のModified Base、v4.0も`CR`/`IR`/`AR`として同じ表記を使う）。
Modified Base メトリクス（v3.1の`MAV`等）は、ユーザーから得た情報が「攻撃条件そのもの」を変える
明確な根拠がある場合のみ追加し、通常はBaseと同じ値を引き継いで構わない（環境メトリクスの主目的は
CR/IR/ARの重み付けで、Modified Baseの精緻化は必須ではない）。
