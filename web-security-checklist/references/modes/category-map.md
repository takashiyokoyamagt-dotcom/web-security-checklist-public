# 変更ファイル → チェックカテゴリ 対応表（モード2のスコープ絞り込み用）

モード2（監査レビュー）では、差分に含まれるファイルからこの表で関連カテゴリを推定し、
該当するカテゴリのRed/Blue Teamペアだけを起動します。判断に迷う場合や複数カテゴリにまたがる場合は、
広めに（関連しそうなものは含める方向で）判定してください。見落としの方が誤検知より悪影響が大きいためです。

| 変更内容の特徴（ファイル名・内容のパターン） | 起動するカテゴリ |
| --- | --- |
| SQL文字列、ORMのクエリ/リポジトリ層、`*.sql`、マイグレーションファイル、DB接続設定 | 入力値検証、データベース |
| ログイン、サインアップ、パスワードリセット、認証ミドルウェア、JWT/セッション周り | 認証、セッション管理 |
| ルーティング定義、権限チェック/ミドルウェア、`role`/`permission`関連、管理画面 | アクセス制御・認可 |
| フォーム入力処理、APIのリクエストパース、ファイルアップロード処理 | 入力値検証、ファイルアップロード・ファイル操作 |
| 暗号化処理、トークン生成、APIキー/シークレットの参照箇所、環境変数の追加 | 暗号・秘密情報管理 |
| エラーハンドラ、例外処理、ロギング設定 | エラー処理・ログ |
| CORS設定、セキュリティヘッダ、HTTPS/TLS設定、`.env`/設定ファイル | 通信・セキュリティ設定 |
| `package.json`/`requirements.txt`/`pom.xml`等の依存追加・更新 | 依存関係管理 |
| ページネーション、一覧取得API、リクエストbodyからモデルを更新する処理 | ビジネスロジック・API設計、アクセス制御・認可 |

## 判定に迷う場合の指針
- 差分が小さくカテゴリが自明でない場合でも、**入力値検証とアクセス制御は多くの機能に関わるため、
  他のカテゴリが1つでも該当するなら合わせて起動することを基本とする**（この2つは横断的に効くため）。
- 純粋なUIの見た目変更（CSS、文言修正のみ等）でロジック・データフローに変更がない場合は、
  カテゴリを起動せず「セキュリティ上の影響なし」として即座に判定してよい（コスト削減）。
- 迷ったらユーザーに「このカテゴリも対象に含めますか？」と確認してもよい。
